## 1. Главная идея

CUBIK — не просто task manager и не отдельный AI-чат. Это единая Life OS, соединяющая шесть человеческих потребностей: время, деньги, направление, развитие, энергию и отношения.

Каждая грань является самостоятельным модулем, но использует общие сущности и контекст. Пример связи:

```text
Цель «Запуск MVP»
  → задача «Подготовить презентацию»
  → блок времени 10:00–11:30
  → расход на подрядчика
  → AI-вывод о риске дедлайна
```

## 2. Зафиксированные продуктовые решения

- `Home AI` отсутствует. AI появляется в обзоре дня, задаче, бюджете, цели и других конкретных контекстах.
- Глобальный интерфейс имеет два уровня навигации: узкая постоянная панель переключает шесть граней, а соседняя сворачиваемая панель показывает функции активной грани.
- Аккаунт находится только в правом верхнем углу.
- Настройки закреплены в нижней части глобальной панели.
- Правая панель показывает подробности выбранного объекта и контекстный AI.
- Любое AI-изменение данных сначала показывается как preview; пользователь подтверждает или отклоняет его. Должна быть возможность Undo.
- Русский язык — основной язык текущего прототипа.

Проверки TypeScript, ESLint и production build прошли; открытие меню и дублирование проверены в браузере. Полный адаптивный проход этого пакета ещё не выполнен.

- сортировка по времени, приоритету и дате создания;
- группировка по списку, приоритету и статусу;
- теги с подсказками уже использованных значений;
- дата, время, длительность, приоритет, список, описание, повторение, связанная цель, подзадачи и метаданные вложений;

AI-зоны не делают демонстрационных model calls. Они показывают место будущего server gateway и подтверждённого flow `preview → confirm → apply → undo`.

## 7. Что нельзя потерять при рефакторинге

- шесть граней CUBIK;
- двухуровневое боковое меню;
- возможность свернуть контекстную панель;
- аккаунт только сверху справа;
- одновременный контекст задачи, времени и цели;
- контекстный, а не отдельный AI;
- preview/confirm/undo для будущих AI-команд;
- понятный интерфейс без перегруженности дашбордными графиками;
- UI не должен знать, используется localStorage или будущий API: граница проходит через service/repository слой;
- migration path локальных данных нельзя ломать без явного version bump.
