# CUBIK: AI handoff

Этот документ — обязательная отправная точка для нового AI или разработчика. Сначала прочитайте `AGENTS.md`, затем этот файл, `ARCHITECTURE.md` и `ROADMAP.md`.

## 1. Главная идея

CUBIK — не просто task manager и не отдельный AI-чат. Это единая Life OS, соединяющая шесть человеческих потребностей: время, деньги, направление, развитие, энергию и отношения.

Каждая грань является самостоятельным модулем, но использует общие сущности и контекст. Пример связи:

```text
Цель «Запуск MVP»
  → задача «Подготовить презентацию»
  → блок времени 10:00–11:30
  → расход на подрядчика
  → AI-вывод о риске дедлайна
```

## 2. Зафиксированные продуктовые решения

- `Home AI` отсутствует. AI появляется в обзоре дня, задаче, бюджете, цели и других конкретных контекстах.
- Глобальный интерфейс имеет два уровня навигации: узкая постоянная панель переключает шесть граней, а соседняя сворачиваемая панель показывает функции активной грани.
- Аккаунт находится только в правом верхнем углу.
- Настройки закреплены в нижней части глобальной панели.
- Правая панель показывает подробности выбранного объекта и контекстный AI.
- Любое AI-изменение данных сначала показывается как preview; пользователь подтверждает или отклоняет его. Должна быть возможность Undo.
- Русский язык — основной язык текущего прототипа.

## 3. Текущий код

Стек: Next.js 16.3.4 App Router, React 19.2, TypeScript, CSS Modules, Lucide React и pnpm.

Важно: эта версия Next.js содержит отличия от более ранних версий. Перед изменением архитектуры или API обязательно прочитайте соответствующий файл в `node_modules/next/dist/docs/` согласно `AGENTS.md`.

Текущий экран `/app/today` — Client Component, потому что содержит локальное состояние и обработчики событий. Данные находятся в `useState`; backend отсутствует.

## 4. Что можно менять сейчас

- размеры, сетку и адаптивность экрана Today;
- типографику, цвета и дизайн-токены;
- структуру компонентов без изменения утверждённой UX-логики;
- демонстрационные данные;
- доступность, клавиатурное управление и состояния элементов;
- временный знак и иконки после утверждения финального брендинга.

## 5. Что нельзя потерять при рефакторинге

- шесть граней CUBIK;
- двухуровневое боковое меню;
- возможность свернуть контекстную панель;
- аккаунт только сверху справа;
- одновременный контекст задачи, времени и цели;
- контекстный, а не отдельный AI;
- preview/confirm/undo для будущих AI-команд;
- понятный интерфейс без перегруженности дашбордными графиками.

## 6. Ближайшая правильная задача

1. Разделить большую страницу на `AppShell`, `DomainRail`, `ModuleSidebar`, `Topbar`, `TaskList`, `Schedule`, `TaskInspector`.
2. Описать доменные типы `Task`, `List`, `Tag`, `Goal`, `CalendarBlock`, `Habit`.
3. Добавить локальный repository/service слой и persistence, не привязывая UI напрямую к будущему API.
4. Реализовать полноценное создание и редактирование задачи: дата, время, длительность, приоритет, список, метки, описание, подзадачи, повторение и вложения.
5. После стабилизации UX подключить настоящую авторизацию и PostgreSQL.

## 7. Правила качества

- Не переписывать весь экран без необходимости: развивать систему поэтапно.
- Не устанавливать библиотеку, если задача чисто решается текущим стеком.
- Не смешивать демонстрационные AI-ответы с настоящими вызовами модели.
- Не хранить ключи провайдеров на клиенте.
- Новая функция должна учитывать loading, empty, error, success и permission states.
- Проверять desktop и mobile.
- Перед завершением запускать `pnpm typecheck`, `pnpm lint`, `pnpm build`.

## 8. Definition of Done следующего этапа

- данные задач сохраняются после перезагрузки;
- задача создаётся и редактируется через единый типизированный поток;
- фильтры Today/Inbox/All используют одно хранилище;
- экран остаётся доступным с клавиатуры;
- UI не ломается на ширинах 390, 768, 1280 и 1440 px;
- документация обновлена вместе с кодом.
